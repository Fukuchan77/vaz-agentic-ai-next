## Most-used commands

Tasks run through **mise** (`mise.toml` is the source of truth — check it before running bare tools):

- `mise run dev` — dev server (Turbopack) on `http://localhost:3000`
- `mise run lint` / `mise run lint:fix` — Biome check / auto-fix
- `mise run typecheck` — `tsc --noEmit`
- `mise run test:run` — Vitest once; single package file: `pnpm exec vitest run --project packages packages/agents/tests/chat-agent.spec.ts`
- `mise run test:e2e` — Playwright; `mise run test:e2e:ollama` for the real chat round-trip against local Ollama
- `mise run size` — client bundle budget (`.size-limit.json`, brotli JS 420 kB / CSS 22 kB); needs `mise run build` first, so it is a separate CI job (`tests.yml` `bundle-size`), not part of `check`
- `mise run check` — the aggregate TS gate (lint + typecheck + test:run + audit + `lint:model-ids`). The two Python lanes gate separately and on purpose: `mise run py:check` (`services/agent`) and `mise run api:check` (`services/api`) are **not** dependencies of `check`, so the TS gate stays green with no Python toolchain installed.
- `docker compose up -d` — local `db`/`redis`/`engine`/`worker` stack, needed for RAG ingest or job/approval work

## Big-picture architecture

- **VAZ stack**: **V**ercel AI SDK 7 (`ai`, `@ai-sdk/react`) + Next.js 16 App Router (Turbopack) + **Z**od v4. React 19.2 with React Compiler; Carbon Design System for UI.
- **Monorepo**: two apps (`apps/web` = `@vaz/web`, `apps/worker` = `@vaz/worker`) over seven source-only `@vaz/*` packages (`schemas`, `db`, `config`, `tools`, `rag`, `agents`, `evals`). One-way dep graph: `schemas`/`db` (leaves) → `config`/`tools`/`rag` → `agents` → `web`/`worker`/`evals`. `@vaz/db` owns all Drizzle table defs (RAG + workflow) and is schema-only — `pg` pools live at composition roots. Packages ship raw TS (no build step, no per-package `tsconfig`); import by path (`@vaz/schemas/deps`). The legacy root `src/`/`tests/` migration (spec `001-vaz-ai-update`) is complete — `apps/web` is the sole source of truth; no application source lives at the repo root.
- **Chat request flow**: `apps/web/src/app/page.tsx` (Server Component) → `features/chat/Chat.tsx` (`"use client"`, `useChat`) → `POST api/chat/route.ts`. The route is a thin HTTP⇔Agent adapter: validate with `chatRequestSchema`, build `AgentDeps` (incl. `runtimeContext` from the OIDC session), then `createChatAgent(deps).stream(...)` and bridge via `toUIMessageStream` → `createUIMessageStreamResponse`. Orchestration (`streamText`, tools, `stopWhen: isStepCount(5)`, RAG retrieval tool) lives in `@vaz/agents`, **not** the route.
- **Durable job flow**: `POST api/jobs` submits a supervisor plan as an Inngest event; `apps/worker` runs `createSupervisorWorkflow(deps).dispatch(...)`, dispatching to specialists (`rag-research`/`document-generation`/`data-processing`); progress fans out over Redis to `GET api/jobs/:id/stream` (SSE) → `useJobStream` → `ApprovalPanel`. Destructive tool calls (`needsApproval: true`) suspend for human approve/reject/edit via `POST api/jobs/:id/approve`, and resume correctly across worker restarts (Inngest owns durability; AI SDK owns the typed approval contract — ADR-2). **`POST api/jobs/:id/approve` is no longer fire-and-forget** (spec `007-cross-repo-adoption-closeout`): strict-schema validation (`z.strictObject`) → consume-once claim → token-budget check (`JOB_TOKEN_BUDGET`, `@vaz/schemas/env`) → audit → resume. Returns `400`/`404`/`409`/`429` instead of passing silently. The decision logic is a pure-function layer in `apps/web/src/lib/approvals.ts` (no HTTP types, no DB, no `new Date()`); pending/consumed state and observed token usage live in the `job_step` table (`packages/db/src/schema.ts`) behind the `JobStepStore` port (`apps/worker/src/stores.ts`).
- **Provider resolution is per-request**: `@vaz/config#resolveModel()` / `resolveEmbeddingModel()` read env (validated by `@vaz/schemas/env`) on every request — switch Anthropic (`claude-opus-5-5`, needs `ANTHROPIC_API_KEY`) ↔ OpenAI (`gpt-6-sol` via `@ai-sdk/openai`, needs `OPENAI_API_KEY`) ↔ Ollama (`granite4.2:latest` default, no key) via `AI_PROVIDER` only, no restart. Adding a provider touches the env enum + default (`@vaz/schemas/env`), `MODEL_ALLOWLIST` (its `satisfies Record<AiProvider, …>` fails typecheck until the new provider has an entry), and `resolveModel`'s switch — embeddings are a separate provider axis (`AI_EMBEDDING_PROVIDER`, Ollama only).
- **Auth + RBAC**: OIDC via Auth.js (Entra ID / Google Workspace, chosen by `AUTH_IDP`). Role is never read from an IdP claim — `apps/web/src/lib/auth.ts` resolves it from the authenticated email through `@vaz/config`'s committed `ADMIN_EMAILS` allowlist, then carries `{ userId, role }` as `AgentDeps.runtimeContext`.
- **Feature-based colocation**: components + scoped `*.module.scss` live together under `apps/web/src/features/*` (`chat/`, `jobs/`). Anything importing `@carbon/react` must be a client component.

## Things that bite

- **Dependency injection (ADR-3)** — agents/capabilities take `AgentDeps<DB>` (`db`, `logger`, `now: Clock`, optional `audit`, optional `runtimeContext`) by constructor. Never `new Date()` inside a tool or agent — read `deps.now()` so time is pinnable in tests.
- **Model IDs live only in `@vaz/config`** (`model-allowlist.ts`) and, as Zod defaults, `@vaz/schemas/src/env.ts` (R1.8/ADR-5). Anywhere else, a grep gate (`lint:model-ids`) fails the build. Never hardcode a model string elsewhere.
- **AI SDK v7 API surface** — `createUIMessageStreamResponse` + `toUIMessageStream`; `stopWhen: isStepCount(n)` (was `stepCountIs` in v6); tool field is `inputSchema` (not `parameters`). Full v7 docs ship in `node_modules/ai/docs/`.
- **Two independent controls on destructive tools** — HITL approval (`needsApproval`, policy in `@vaz/agents`) and a committed recipient allow-list (`RECIPIENT_ALLOWLIST` in `packages/tools/src/allowlist.ts`) are separate gates; neither substitutes for the other. Both allow-lists (`ADMIN_EMAILS`, `RECIPIENT_ALLOWLIST`) ship empty — add entries as reviewed, committed code changes, never via env.
- **Prompt-injection defense** — RAG results are wrapped as explicitly delimited context blocks (`packages/agents/src/prompt.ts`); once injected, `externallyDriven` is sticky for the rest of the run and forces approval-capable tools into `'user-approval'` even after the delimiter scrolls out of context.
- **Tool-execution audit log has one firing point** — `@vaz/agents`'s lifecycle hook (`audit-hook.ts`) records every tool call for both web and worker paths; persistence is injected via `deps.audit` (`apps/web/src/lib/audit.ts`, `apps/worker/src/audit.ts`). Never log raw prompts or raw tool args/output outside the audit sink (R4.7 privacy contract). Approval decisions have a **separate, single firing point** in `apps/web/src/lib/approvals.ts` (`recordApprovalDecisions`), which logs only edited-arg key names (not values) and is fail-soft (audit failure does not fail the resume).
- **RAG embedding dimension is DDL-fixed** (768, Ollama `nomic-embed-text` default, `EMBEDDING_DIM` in `packages/db/src/schema.ts`) — changing embedding provider/model requires a migration + full re-ingest; `assertNoProviderMixing` refuses to mix provenance in one corpus. Baseline DDL is hand-written SQL in `packages/db/drizzle/`; apply via `mise run db:migrate` (drizzle-kit not adopted; drift test in `packages/db/tests/` guards alignment).
- **`apps/worker` is engine-agnostic except one file** — only `apps/worker/src/inngest.ts` imports the Inngest SDK; everything else operates on ports (`DurableEngine`, `JobEventSink`, `AuditSink`, `JobStore`, `JobStepStore`) so the engine could be swapped.
- **Approval-path invariants are order- and idempotency-sensitive** — four rules that unit tests pin and that look like harmless refactors from the outside: (1) `registerPending` is awaited in the *same* synchronous path immediately before the approval gate, with no intervening `await`, or a resume can arrive before the pending row exists; (2) `recordStepUsage` writes the observed `totalTokens` as an **absolute** value (`ON CONFLICT … SET`, never `+=`) so an Inngest function-body replay does not double-count — cumulative spend is a `SUM`; (3) `claimPending` consumes the pending rows whether or not the budget check then fails, so a `429` caller cannot replay the same target; (4) `submitApproval` sends with idempotency key `"<jobId>:<stepId>"`, so a duplicated submission collapses to one resume. Every store write is idempotent because Inngest re-runs the function body on retry and resume.
- **Existence concealment on the approve route** — unknown / in-flight / consumed approval targets deliberately collapse into one `404`. Do not split them into distinct statuses or messages "for better errors"; the collapse is what stops a non-owner enumerating job state.
- **Test agents without a network** — inject `MockLanguageModelV4` (`ai/test`) via the `model` seam on `createChatAgent`; `simulateReadableStream` feeds chunks. Vitest projects: `web` (jsdom), `worker` (node), `packages` (node, incl. `@vaz/evals`'s `src/unit/**`), and `repo` (node, `tests/repo/**` — CI / dependabot / container-toolchain-pin / network / cross-repo-reference / model-ID / doc-link / OWASP-citation / egress-bypass governance guards). Each `repo` guard asserts "scanned > 0" before asserting anything else — a guard that silently scans nothing is the exact failure mode they exist to prevent, so never narrow a scan without checking that assertion still holds.
- **Two documentation-writing rules the `repo` guards enforce** — a document *in this repo* must be reachable by a relative Markdown link (`doc-links.spec.ts`; a "canonical" source that only ever appeared as a code span is how the cross-repo review stayed missing for months), while a path in *another* repository stays a code span (the guard cannot reach it and would flag the link). `owasp-mapping-citations.spec.ts` additionally pins the two OWASP mapping docs' citation paths, cited symbols, CI step names, 3-value status vocabulary, and taxonomy version dates — renaming a symbol or a CI step breaks those docs, not just the code.
- **Every env read in `packages/*` goes through `@vaz/schemas/env`** — no bare `process.env.X`; readers take an injectable `env` param defaulting to `process.env`. `TOOL_APPROVAL_SECRET` shows the stakes: it is optional, and unset it means the AI SDK stops HMAC-binding `tool-approval-request`s, so the stateless chat path trusts a client-supplied `approval.id` and the HITL gate becomes a rubber stamp (`RECIPIENT_ALLOWLIST` is then the only control). `buildStreamTextOptions` warns once per run when it is unset, and never logs its value.
- **`MAX_PLAN_STEPS` bounds a supervisor plan** (`packages/schemas/src/workflows.ts`, 20) — the plan is client-supplied on `POST /api/jobs` and every step is an LLM call, so its length is the request's cost multiplier. `JOB_TOKEN_BUDGET` does not cover this: it is read only on the approval-resume path, which an approval-free plan never reaches.
- **Telemetry is fail-soft** — `instrumentation.ts` calls `registerOTel` *then* `initTelemetry` (provider before AI SDK bridge); neither throws.
- **Carbon styles** — never `@use "@carbon/react"` wholesale; add per-component entries to `apps/web/src/assets/styles/global.scss`. Carbon usage requires `"use client"`.
- **Git hooks are checked in** (`.githooks/`, activated by the `prepare` script): pre-commit runs gitleaks (staged diff) + biome + tsc + vitest + audit + model-ids; pre-push runs Playwright E2E. The secret scan is deliberately **first**: a secret that reaches a commit object is not undone by the next commit, it has to be rewritten out of history, so it is the one check whose failure gets more expensive the later it is caught.
- **Secret scanning is `gitleaks git`, never `gitleaks dir`** — `dir` walks the filesystem and so reads `node_modules/`, `.venv/` and `apps/web/.next/` (456 MB, and third-party findings this repo cannot act on); `git` reads tracked git content only (9.93 MB). `mise run secret-scan` is the full-history scan (also `security-daily.yml`'s `secret-scan` job, which needs `fetch-depth: 0` or it scans one commit and passes), `secret-scan:staged` is the pre-commit leg. `.gitleaksignore` is the baseline of 242 confirmed false positives, all from the `services/api` subtree import; entries are exact `<commit>:<file>:<rule>:<line>` fingerprints — **regenerate with `mise run secret-scan:report`, never hand-edit a line**. Every scan that writes to a log passes `--redact`, so a true positive is not republished into build output that outlives the incident.
- **Vitest 4, TypeScript 6, and `@types/node` 24 are held on purpose** — newer majors exist for all three. Vitest 5 resets mock state between tests by default and breaks `apps/web/tests/auth.spec.ts`'s cross-test `NextAuthMock.mock.calls` read; TS 7 is the native port (ADR-level); `@types/node` tracks the pinned Node 24 LTS runtime. See the bullet in [AGENTS.md](AGENTS.md) before bumping any of them.
- **Container base images are only watched by Dependabot** (`docker` + `docker-compose` ecosystems) — they resolve at `docker build` time and appear in no lockfile, so `pnpm audit` / `pip-audit` / `security-daily.yml` are all blind to them. `apps/worker/Dockerfile`'s `ARG NODE_VERSION` / `ARG PNPM_VERSION` are outside even that (Dependabot cannot resolve an ARG-interpolated `FROM` tag): they track `mise.toml`'s `[tools] node` and root `package.json`'s `packageManager`, pinned by `tests/repo/container-toolchain-pins.spec.ts`. That guard exists because the pnpm 11→12 bump left the Dockerfile on 11.10.0 with every gate green — nothing in `mise run check` builds the image.
- **New deps with install scripts** must be recorded in `allowBuilds` in `pnpm-workspace.yaml` and set to `true` to run (entries default to `false` = denied; presence alone is just an audited decision). Versions younger than 24h won't resolve (`minimumReleaseAge`).
- Use `import type` (enforced by Biome + `verbatimModuleSyntax`). Vitest globals (`test`/`expect`/`vi`) need no imports.
