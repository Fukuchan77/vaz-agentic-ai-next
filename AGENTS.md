## Big-picture architecture

- **Stack**: Vercel AI SDK 7 (`ai`, `@ai-sdk/react`) + Next.js 16 App Router (Turbopack) + Zod v4. React 19.2 with React Compiler. UI is shadcn/ui + Tailwind CSS v4 (Carbon retired, [ADR-0008](docs/adr/0008-ui-component-standard.md)).
- **Monorepo**: two apps (`apps/web` = `@vaz/web`, `apps/worker` = `@vaz/worker`) over seven source-only `@vaz/*` packages (`schemas`, `db`, `config`, `tools`, `rag`, `agents`, `evals`). One-way dep graph: `schemas`/`db` (leaves) → `config`/`tools`/`rag` → `agents` → `web`/`worker`/`evals`. `@vaz/db` owns all Drizzle table defs and is schema-only; `pg` pools live at composition roots. Packages ship raw TS with no build step and no per-package `tsconfig`. `apps/web` is the sole source of truth for the app; no application source lives at the repo root.
- **Chat request flow**: `apps/web/src/app/page.tsx` (Server Component) → `features/chat/Chat.tsx` (`"use client"`, `useChat`) → `POST api/chat/route.ts`. The route is a thin HTTP⇔Agent adapter: validate with `chatRequestSchema`, build `AgentDeps` (incl. `runtimeContext` from the OIDC session), call `createChatAgent(deps).stream(...)`, and bridge with `toUIMessageStream` → `createUIMessageStreamResponse`. Orchestration (`streamText`, tools, `stopWhen: isStepCount(5)`, the RAG retrieval tool) lives in `@vaz/agents`, not the route.
- **Durable job flow**: `POST api/jobs` submits a supervisor plan as an Inngest event; `apps/worker` runs `createSupervisorWorkflow(deps).dispatch(...)`, which dispatches to specialists (`rag-research` / `document-generation` / `data-processing`). Progress fans out over Redis to `GET api/jobs/:id/stream` (SSE) → `useJobStream` → `ApprovalPanel`. Destructive tool calls (`needsApproval: true`) suspend for human approve/reject/edit and resume across worker restarts (Inngest owns durability; AI SDK owns the typed approval contract, ADR-2). `POST api/jobs/:id/approve` is not fire-and-forget (spec `007`): strict-schema validation (`z.strictObject`) → consume-once claim → token-budget check (`JOB_TOKEN_BUDGET`, `@vaz/schemas/env`) → audit → resume, returning `400`/`404`/`409`/`429` instead of passing silently. Its decision logic is pure in `apps/web/src/lib/approvals.ts`; state lives in the `job_step` table (`packages/db/src/schema.ts`) behind `JobStepStore` (`apps/worker/src/stores.ts`).
- **Provider axes**: chat model resolution is per request (`@vaz/config#resolveModel()`); embeddings are a separate axis (`AI_EMBEDDING_PROVIDER`, Ollama only). Switching chat provider needs no restart.
- **Feature colocation**: components live under `apps/web/src/features/*` (`chat/`, `jobs/`) and shared primitives under `apps/web/src/components/`. Styling is Tailwind utilities only; no SCSS or Carbon in `apps/web`.
- **Local runtime**: the Python sidecar `services/agent` (port 8000) and `services/api` (port 8001) are separate lanes; `services/agent` stays stateless and never writes the database.

## Code Style & Language Conventions

### TypeScript (Web & Packages)
- **Formatting**: Tabs, double quotes, 100-char line width (enforced by Biome and `.editorconfig`).
- **Imports & Types**: `import type` is mandatory for type-only imports (`verbatimModuleSyntax: true` + `isolatedModules: true` + Biome `useImportType`).
- **Package Imports**: Source-only packages (`packages/*`) use `"exports": {"./*": "./src/*.ts"}`. No package-level build step or per-package `tsconfig.json`. Use subpath imports (e.g. `@vaz/schemas/deps`).
- **Self-referencing imports in `@vaz/rag`**: Node native ESM ingest CLI requires `@vaz/rag/retrieve/index` rather than relative extensionless imports `../retrieve/index`.
- **Globals**: Vitest globals (`test`, `expect`, `vi`, `describe`, `beforeEach`) require no imports.
- **Dependency Injection**: Always pass `deps: AgentDeps` (`db`, `logger`, `now: Clock`, optional `audit`, `runtimeContext`). Never invoke `new Date()` in agents/tools — use `deps.now()`.
- **React 19 & Next.js**: React Compiler is enabled (`reactCompiler: true`); do not add manual `useMemo` or `useCallback`.
- **UI components**: `apps/web` uses shadcn/ui + Tailwind CSS v4 (Carbon fully retired in spec 009 §4, [ADR-0008](docs/adr/0008-ui-component-standard.md)). Write all new components with shadcn primitives (`apps/web/src/components/ui/`) and Tailwind utilities. Do NOT add `@carbon/react` or `@carbon/styles`. The Tailwind entry is `apps/web/src/assets/styles/tailwind.css`; theme tokens and the single `@import "tailwindcss"` live there. No SCSS files remain in `apps/web`.
- **`next-auth` stays on v5 beta**: `next-auth@5.0.0-beta.*` is intentionally pinned (v5 is the only release with `peerDependencies: next ^14||^15||^16`). Do not upgrade to stable without checking peer compat. In Vitest, `next-auth` must be fully mocked via `vi.mock("next-auth", ...)` — its `lib/env.js` imports a bare `next/server` specifier that Vite/Vitest cannot resolve without Turbopack. The canonical mock pattern is in `apps/web/tests/auth.spec.ts`.

### Python (`services/agent` & `services/api`)
- **`services/agent`**: `from __future__ import annotations` required on every module; ruff (line length 100, py313); pyright in strict mode. Snake_case for Pydantic schema fields.
- **`services/api`**: Type checker is `ty` in strict mode (not mypy); Ruff with `S`, `ANN`, `D` (Google-style docstrings), `B`, `SIM`. `force-single-line = true` imports. Python pinned strictly to 3.14 by `services/api/.python-version` (the lane's source of truth, read by uv; the Docker images and Ruff target follow it, and root `mise.toml` carries no Python pin). `services/agent` stays on 3.13 by its own `.python-version`; 3.15 is not adopted until `onnxruntime`/`torch` ship cp315 wheels. All env access must go through `Settings` / `get_settings()`.
- **`services/api` is the single source of truth for the FastAPI + Pydantic AI lane** ([ADR-0007](docs/adr/0007-fastapi-single-source-of-truth.md)). The former standalone `fastapi-pydantic-ai-agent` repository is archived (read-only); fix and evolve the lane here only. Its git-hook checks run as legs of the root `.githooks/` via `services/api/scripts/hooks/{pre-commit,pre-push}.sh`.

## Non-Obvious Architecture & Critical Constraints

- **Chat providers are `anthropic` / `openai` / `ollama`** (`AI_PROVIDER`, resolved per request by `@vaz/config#resolveModel`). The env enum, `MODEL_ALLOWLIST` and `resolveModel`'s switch move together; the allow-list's `satisfies Record<AiProvider, …>` makes a missing entry a type error. API keys (`ANTHROPIC_API_KEY`, `OPENAI_API_KEY`) are read by the provider SDKs themselves.
- **Auth + RBAC** (ADR-0006): Auth.js (`next-auth@5`, JWT strategy) handles OIDC. IdP is switched via `AUTH_IDP=entra-id|google-workspace` (same env-only pattern as `AI_PROVIDER` — no restart). Role is **never** read from an IdP claim — `apps/web/src/lib/auth.ts` resolves `VazRole` from the authenticated email through `@vaz/config/role-allowlist.ts` (`ADMIN_EMAILS`, ships empty). Adding an admin is a committed code change to `ADMIN_EMAILS`, not an env toggle. Provider credentials (`AUTH_MICROSOFT_ENTRA_ID_ID/SECRET`, `AUTH_GOOGLE_ID/SECRET`) and `AUTH_SECRET` are auto-detected by Auth.js from env by naming convention; only the Entra ID `issuer` is passed explicitly (no fixed value to infer).
- **Client bundle budget**: `.size-limit.json` caps `apps/web` client JS/CSS (brotli): JS 420 kB, CSS 4.0 kB (Carbon retired, Tailwind-only; measured 2.95 kB post-§4). Raise the limit only as a reviewed change with the measured size in the commit message.
- **Single Hardcoded Model ID Rule (R1.8/ADR-5)**: Hardcoded model strings are ONLY allowed in `packages/config/src/model-allowlist.ts` (and default fallback in `@vaz/schemas/src/env.ts` / `services/agent/app/config.py`). `scripts/forbid-model-ids.sh` enforces this at build/CI time.
- **Dependency Graph Direction**: `@vaz/schemas` and `@vaz/db` are leaf packages (zero `@vaz/*` runtime imports). Next: `@vaz/config`, `@vaz/tools`, `@vaz/rag`. Next: `@vaz/agents`. Top: `apps/web`, `apps/worker`, `@vaz/evals`. Never create circular dependencies.
- **RAG Provenance & Embeddings**: Dimension is DDL-fixed at 768 (`EMBEDDING_DIM`). `assertNoProviderMixing` forbids mixing embedding providers/models in a single corpus without migration and full re-ingest.
- **Hermetic Unit Tests**: TypeScript unit tests block real network requests via `tests/setup/hermetic-network.ts` (unmocked network calls throw immediately). Python unit tests use in-process ASGI transports or `FunctionModel`.
- **TS ⇔ `services/api` bridge** (spec 008): `POST /api/agent-api/stream` (`apps/web`) relays `services/api`'s `/v1/agent/stream` through `@/lib/agent-api`, holding `API_SERVICE_KEY` server-side (`@vaz/schemas/api-service-env`; default URL port **8001**, since `services/agent` owns 8000). It requires a signed-in session and deliberately accepts **no `session_id`**: every web user shares one service key, hence one `services/api` principal, so a forwarded id would cross users. The 5-event SSE union lives in `@vaz/schemas/api-service`; a change on either side is caught by `packages/schemas/tests/api-service-contract-drift.spec.ts` (TS vs snapshots) and `services/api/tests/unit/test_hub_contract_snapshot.py` (live app vs snapshots) — fix with `mise run openapi:gen`.
- **Single-Writer DB Principle**: pgvector embeddings are written exclusively by TS (`packages/rag`). Python sidecars are stateless and never write to the database.
- **AI SDK v7 Conventions**: Use `createUIMessageStreamResponse({ stream: toUIMessageStream({ stream: result.stream }) })`. Multi-step tool use uses `stopWhen: isStepCount(n)`. Tool definition takes `inputSchema:` (not `parameters:`). `stepCountIs` was renamed `isStepCount` in v7. Full v7 docs ship in `node_modules/ai/docs/`.
- **Zod v4 Usage**: Use `z.looseObject()`, `z.url()`, `z.email()`, `z.iso.datetime()`, `z.uuid()`.
- **Strict Request Objects**: Approval requests and agent API routes use `z.strictObject` / Pydantic `extra="forbid"`. Extra client fields (e.g. injected messages/history/model) are rejected.
- **Privacy Contract**: Loggers (`logger.info/warn/error`) must never log raw user prompts or raw tool arguments/output. The Audit sink is the only approved store for tool execution arguments.
- **All env reads go through `@vaz/schemas/env`**: `packages/*/src` contains no bare `process.env.X` lookups — every reader takes an injectable `env` parameter defaulting to `process.env` and parses it with the Zod schema. `TOOL_APPROVAL_SECRET` is the case that proves why: it is the HMAC key the AI SDK signs `tool-approval-request`s with, it is **optional**, and when unset the stateless chat path re-synthesizes approval requests from the client's own `approval.id` — the HITL gate silently degrades to a rubber stamp and `RECIPIENT_ALLOWLIST` is the only control left. `buildStreamTextOptions` warns once per run when it resolves to `undefined` (never logging the value).
- **Supervisor plans are capped at `MAX_PLAN_STEPS`** (`packages/schemas/src/workflows.ts`, currently 20). The plan arrives from the client on `POST /api/jobs` and every step is dispatched as an LLM call, so the array length is the request's cost multiplier. `JOB_TOKEN_BUDGET` does **not** bound this — it is only consulted on the approval-resume path, which a plan with no approval-gated step never reaches. Raising the cap is a reviewed, committed change, not an env toggle.
- **Worker TypeScript loader** ([ADR-0010](docs/adr/0010-worker-typescript-loader.md)): `apps/worker` loads source-only `@vaz/*` through `module.registerHooks()` with `stripTypeScriptTypes` in `mode: "strip"` (works on Node 24 and Node 26; `"transform"` and `module.register()` are gone or deprecated in Node 26). Strip mode rejects non-erasable syntax (`enum`, `namespace`, parameter properties) — `erasableSyntaxOnly` stops it at typecheck, so never add such syntax to code the worker loads. The image installs pnpm with `npm install --global` because Node 25+ images ship no corepack.
- **Pivotal Major Pins**: Root workspace uses `typescript` 7.x; `@vaz/schemas` isolates `typescript` 6.0.3 for `openapi-typescript` codegen (ADR-0009). `@types/node` stays on `^26` (matches Node 26 LTS). `vitest` / `@vitest/coverage-v8` are on 5.x, which defaults to `clearMocks: true`: a mock's call history is emptied before each test, so a test must not read calls made by an earlier test or at module load — capture them in `beforeAll` (see `apps/web/tests/auth.spec.ts`).
- **Tool-execution audit log has one firing point** — `@vaz/agents`'s lifecycle hook (`audit-hook.ts`) records every tool call for both web and worker paths; persistence is injected via `deps.audit` (`apps/web/src/lib/audit.ts`, `apps/worker/src/audit.ts`). Approval decisions have a **separate, single firing point** in `apps/web/src/lib/approvals.ts` (`recordApprovalDecisions`), which logs only edited-arg key names (not values) and is fail-soft (audit failure does not fail the resume).
- **Two independent controls on destructive tools** — HITL approval (`needsApproval`, policy in `@vaz/agents`) and a committed recipient allow-list (`RECIPIENT_ALLOWLIST` in `packages/tools/src/allowlist.ts`) are separate gates; neither substitutes for the other. Both allow-lists (`ADMIN_EMAILS`, `RECIPIENT_ALLOWLIST`) ship empty — add entries as reviewed, committed code changes, never via env.
- **Prompt-injection defense** — RAG results are wrapped as explicitly delimited context blocks (`packages/agents/src/prompt.ts`); once injected, `externallyDriven` is sticky for the rest of the run and forces approval-capable tools into `'user-approval'` even after the delimiter scrolls out of context.
- **Approval-path invariants are order- and idempotency-sensitive** — four rules that unit tests pin and that look like harmless refactors from the outside: (1) `registerPending` is awaited in the *same* synchronous path immediately before the approval gate, with no intervening `await`, or a resume can arrive before the pending row exists; (2) `recordStepUsage` writes the observed `totalTokens` as an **absolute** value (`ON CONFLICT … SET`, never `+=`) so an Inngest function-body replay does not double-count — cumulative spend is a `SUM`; (3) `claimPending` consumes the pending rows whether or not the budget check then fails, so a `429` caller cannot replay the same target; (4) `submitApproval` sends with idempotency key `"<jobId>:<stepId>"`, so a duplicated submission collapses to one resume. Every store write is idempotent because Inngest re-runs the function body on retry and resume.
- **Existence concealment on the approve route** — unknown / in-flight / consumed approval targets deliberately collapse into one `404`. Do not split them into distinct statuses or messages "for better errors"; the collapse is what stops a non-owner enumerating job state.
- **`apps/worker` is engine-agnostic except one file** — only `apps/worker/src/inngest.ts` imports the Inngest SDK; everything else operates on ports (`DurableEngine`, `JobEventSink`, `AuditSink`, `JobStore`, `JobStepStore`) so the engine could be swapped.
- **RAG DDL** — baseline DDL is hand-written SQL in `packages/db/drizzle/`, applied via `mise run db:migrate` (drizzle-kit not adopted; a drift test in `packages/db/tests/` guards alignment with `packages/db/src/schema.ts`). Changing the embedding provider/model means a migration plus full re-ingest (see RAG Provenance above).
- **Test agents without a network** — inject `MockLanguageModelV4` (`ai/test`) via the `model` seam on `createChatAgent`; `simulateReadableStream` feeds chunks. Vitest projects: `web` (jsdom), `worker` (node), `packages` (node, incl. `@vaz/evals`'s `src/unit/**`), and `repo` (node, `tests/repo/**` — CI / dependabot / container-toolchain-pin / network / cross-repo-reference / model-ID / doc-link / OWASP-citation / egress-bypass governance guards). Each `repo` guard asserts "scanned > 0" before asserting anything else — a guard that silently scans nothing is the exact failure mode they exist to prevent, so never narrow a scan without checking that assertion still holds.
- **Two documentation-writing rules the `repo` guards enforce** — a document *in this repo* must be reachable by a relative Markdown link (`doc-links.spec.ts`; a "canonical" source that only ever appeared as a code span is how the cross-repo review stayed missing for months), while a path in *another* repository stays a code span (the guard cannot reach it and would flag the link). `owasp-mapping-citations.spec.ts` additionally pins the two OWASP mapping docs' citation paths, cited symbols, CI step names, 3-value status vocabulary, and taxonomy version dates — renaming a symbol or a CI step breaks those docs, not just the code.
- **`/api/agent-api/stream` is the only TS → `services/api` call, and it is stateless on purpose** — see the bridge bullet above; the contract-drift guards fail on boundary drift and `mise run openapi:gen` regenerates.
- **Each Python lane pins its own interpreter** — moving one lane never moves the other. `services/api` runs its tests with `filterwarnings = ["error::DeprecationWarning"]`, so an interpreter bump there is a warnings re-census, not a one-line change (3.14 once failed 63 tests on that alone). 3.15 is out until `onnxruntime`/`torch` publish cp315 wheels (constitution 2.3.0).
- **Telemetry is fail-soft** — `instrumentation.ts` calls `registerOTel` *then* `initTelemetry` (provider before AI SDK bridge); neither throws.
- **Git hooks are checked in** (`.githooks/`, activated by the `prepare` script): pre-commit runs gitleaks (staged diff) + biome + tsc + vitest + audit + model-ids, then the `services/api` leg (`services/api/scripts/hooks/pre-commit.sh`, a no-op unless that lane is staged); pre-push runs the `services/api` Ollama-gated leg (only when a pushed commit touches the lane) and then Playwright E2E. The secret scan is deliberately **first**: a secret that reaches a commit object is not undone by the next commit, it has to be rewritten out of history, so it is the one check whose failure gets more expensive the later it is caught.
- **Secret scanning is `gitleaks git`, never `gitleaks dir`** — `dir` walks the filesystem and so reads `node_modules/`, `.venv/` and `apps/web/.next/` (456 MB, and third-party findings this repo cannot act on); `git` reads tracked git content only (9.93 MB). `mise run secret-scan` is the full-history scan (also `security-daily.yml`'s `secret-scan` job, which needs `fetch-depth: 0` or it scans one commit and passes), `secret-scan:staged` is the pre-commit leg. `.gitleaksignore` is the baseline of 244 confirmed false positives, all `services/api` test placeholders (242 from the subtree import, 2 from the spec `008` port of upstream `d9a3c93` — that port's fingerprints pin its commit SHA, so merge branches carrying it with a merge commit, never squash/rebase); entries are exact `<commit>:<file>:<rule>:<line>` fingerprints — **regenerate with `mise run secret-scan:report`, never hand-edit a line**. Every scan that writes to a log passes `--redact`, so a true positive is not republished into build output that outlives the incident.
- **Container base images are only watched by Dependabot** (`docker` + `docker-compose` ecosystems) — they resolve at `docker build` time and appear in no lockfile, so `pnpm audit` / `pip-audit` / `security-daily.yml` are all blind to them. `apps/worker/Dockerfile`'s `ARG NODE_VERSION` / `ARG PNPM_VERSION` are outside even that (Dependabot cannot resolve an ARG-interpolated `FROM` tag): they track `mise.toml`'s `[tools] node` and root `package.json`'s `packageManager`, pinned by `tests/repo/container-toolchain-pins.spec.ts`. That guard exists because the pnpm 11→12 bump left the Dockerfile on 11.10.0 with every gate green — nothing in `mise run check` builds the image.
- **New deps with install scripts** must be recorded in `allowBuilds` in `pnpm-workspace.yaml` and set to `true` to run (entries default to `false` = denied; presence alone is just an audited decision). Versions younger than 24h won't resolve (`minimumReleaseAge`).
